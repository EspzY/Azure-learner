# AzureLab landing and ephemeral Laboratory — PR71

Owner direction (9 November 2026): opening the Laboratory from the main landing must lead to the newly developed 3.7 Portal, with a usable public demonstration **even if a PostgreSQL database has not been provisioned**. Root, course and both Portal modes must have an obvious return. The three course tiles and independent Laboratory tile remain the only root entrypoints. Do not merge, deploy or migrate existing data.

## Explicit behavior

1. Root `/` is still a read-only landing. AZ-900 enters existing `/learn`, AZ-104/AZ-305 remain planned nonlinks; free Lab enters `/labs/laboratory`. The available AZ-900 card and Laboratory tile have a single semantically real, expanded link target. Hover/focus lift the cards; ordinary unmodified click uses a 160ms zoom cue, with **no delay or motion** for users requesting reduced motion. Modified clicks retain native link behavior. There is no new progress, completed badge or completion issuer.
2. Free Laboratory checks its existing database-backed session as before. When this is unavailable, the page offers an **explicit** `Start midlertidig Sandbox uten lagring`. It is not an automatic fallback that silently changes the authority of an active server-backed workspace.
3. The new browser-memory workspace uses the exact frozen `laboratory@3.0.0`–`3.7.0` `freshWorld`, `execute`, `replay` and analysis dispatch. It is the same implemented capability set, not a replacement rules engine. State is kept only in a module variable within the current loaded browser document. There is no localStorage, IndexedDB, sessionStorage, database, login, cookie, credential, Azure API, or session migration.
4. `POST /api/laboratory/ephemeral` is a stateless, Node-based evaluator, bounded to 768 KiB input. It checks origin/fetch metadata, fresh model selection, versioned replay of the entire supplied history, identical World projection and request/workspace preconditions **before** running the unchanged domain evaluator. Reviews are non-mutating; commands return original typed receipts and newly derived snapshots; duplicate IDs return original receipts and inconsistent duplicates are rejected. Historical through, routing and policy diagnostics reuse the authoritative domain algorithms. Responses are `no-store`, never `Set-Cookie`.
5. **The browser is the sole owner of the memory snapshot.** Even when the server reruns the engine, the client controls what history it submits. This is explicitly **untrusted demonstration evidence**, not secure persistence, tamper-resistant attestation, course mastery, security improvement, certification or multi-tab concurrency. Reload clears it. Different tabs do not synchronize. Lost network responses do not indicate a durable commit.
6. Real server-backed Laboratory behavior remains on its original routes and PostgreSQL authority. We do not change database migrations, sessions, original receipts, existing models or course/learning stores. This implementation makes no promise that the existing course `/portal` v2 workspace is already integrated with v3.7. The AZ course's top-bar free Sandbox shortcut now points to v3.7; guided course tasks **still use** the original v2 Portal while a separately versioned course-to-Laboratory adapter awaits design and authorization.

## Navigation and presentation

A visible `Til forsiden` link is placed at the right side of the regular AZ-900 course header, course Portal header and free Laboratory header. Compact Portal headers keep the home icon with an accessible name. The existing Portal brand still returns to the current Portal's internal home, so navigation scopes remain distinct. Landing retains its read-only AZ-900 in-progress projection and planned courses. Existing course origins and backwards navigation remain unchanged.
