## Read-only first-initiation analysis

Input selects actual source/destination NICs, TCP or UDP and one source/destination port0–65535. IPs come from persisted NICs, never a manually supplied positive packet fixture. Results bind workspace/model/revision/source/destination and the five-tuple. No command/event/receipt or course state is written by analysis. Missing/corrupt historical evidence fails closed through the original repository. Result input is locked while awaiting the original server response; workspace/revision changes invalidate the view.

First reuse the frozen Part B route selector through a read-only3.2-shaped projection, preserving its LPM/source-priority, nontransitivity and unsupported exceptions. A selected None is a modeled routing drop. A supported forward path must be local VNet→actual same-VNet destination, or a direct Connected peering route that names the actual destination VNet. Internet, ambiguous routing, self-NIC/loopback, overlapping different-VNet endpoint identities and unsupported paths cannot be treated as arrival. Neither selected route nor NSG Allow establishes a return path, VM/application availability or actual traffic.

For a supported forward path evaluate, in this order:

1. Source NIC outbound NSG.
2. Source subnet outbound NSG.
3. Destination subnet inbound NSG.
4. Destination NIC inbound NSG.

No association means no NSG restriction at that layer, not an invented matching rule. A deny or undetermined layer stops later layers, visibly marked not evaluated. Within an NSG, use the existing custom rule records and frozen default-rule reference, ascending numeric priority, exact direction/protocol/address/port matching, first decisive match. Custom priorities100–4096 precede defaults65000/65001/65500. Do not use a universal Deny-over-Allow heuristic. Trace mismatches, the decisive original rule and unprocessed later rules. Rules after a winner never influence the result.

## Partial service-tag knowledge

Service tags are symbolic Azure-maintained sets. VirtualNetwork is **not** all private IPv4. Microsoft includes local ranges, peer ranges, on-premises/gateway/host ranges and UDR contributions; it can contain default routes. This profile proves only positive membership in the actual local VNet or a direct Connected peer. Outside these guaranteed ranges membership is **unknown**, even for another RFC1918 address. Do not guess UDR/host/on-premises contributions or prove exclusion from incomplete data.

Internet membership is unknown: no arbitrary public/private CIDR complement or static allowlist is used. AzureLoadBalancer membership is unknown: the model contains neither a load balancer nor probe traffic, and never treats an arbitrary NIC packet as a health probe. These limitations are explicit in rule traces. AND matching is three-valued: a definite mismatch makes a rule nonmatching; otherwise any unknown condition makes it undetermined. A potentially matching unknown rule before a decisive later rule prevents a fabricated Allow/Deny. A higher-priority definite custom match remains decisive before unresolved defaults. Existing custom-rule input remains IPv4/CIDR/* and single-port/*; new custom service-tag/ASG/range expressions stay unsupported.

Use these aggregate statuses only: **Allowed by modeled network policy**, **Denied by modeled network policy**, **Dropped by modeled routing**, **Undetermined / Unsupported**. This is a hypothetical new initiation. No established-state tracking, packets, VM/OS firewall, NAT, load balancing, real Network Watcher or connection-success/verified-connectivity claim.
