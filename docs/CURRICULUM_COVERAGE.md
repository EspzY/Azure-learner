# Curriculum coverage audit

Baseline **33f4f690** (G1.1), candidate L1 / inventory1.0.0 / source review **2026-10-23**. This audit separates a planned competency from actual manuscript, teaching, practice, assessment and evidence. No human SME or learner study has been performed. Source review here means author cross-check of the stated scope, not professional accreditation. Microsoft lessons/assessments are not imported.

## What existed before L1

The 30 competency units were an extensive **blueprint**, not 30 taught units. `src/domain/rpg/story.ts` contained 23 conversation nodes with original responsibility/hosting explanations, model switching and two immediate guided questions. `src/domain/expedition.ts` supplied the same responsibility mechanics and two guided detours. The legacy three-question assessment concerned scopes/locations. The real Chapter01 guided engine modeled groups, Linux plan/app dependencies and a custom location-deny rule, including prediction and causal explanation. None had independent transfer, retention evidence or complete Chapter01 promotion. Source-register entries did not constitute authored lessons.

Before L1, substantial gaps included cloud provisioning versus owned infrastructure, private/public/hybrid boundaries and use cases, capacity economics, consumption meters and pricing commitments. RPG prose was meaningful but narrow; optional field notes were not a reusable curriculum manuscript/journal system. Existing legacy XP120 measures participation only.

## Wider curriculum and explicit next work

The existing [30-competency graph](LEARNING_JOURNEY.md) remains the professional scope: F foundations; G governance; N networking; C compute/apps; D storage/data/integration; I identity/security; O operations; A automation/DevOps; R architecture/advisory. Specialist X tracks cover advanced networks, security, data/AI, hybrid and platforms. These are capabilities, often requiring several modules and scenarios each. F01 currently conflates service selection and deployment concepts; L1 refines it into seven stable module objectives without renaming F01. F03 spans consumption, scaling, reliability and cost; L1 teaches only its consumption/capacity/pricing subset.

Next author a complete service-types module connecting this module's responsibility boundary to the existing App Service quest, including VM/SaaS counterexamples, followed by benefits/failure-boundary material. Networking/identity and operations must introduce actual flow/access/telemetry models, not re-skin capacity bars. Experienced entry uses the first changed-task submission; skipping dialogue or self-reported experience supplies no evidence. Human SME review of L1 and beginner/engineer walkthroughs are release gates before declaring production educational acceptance.
