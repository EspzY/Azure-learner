# Security and privacy

## Portal reboot boundary — 2026-10-24

The Portal is an independent simulator, visibly labelled and unaffiliated with Microsoft. It has no account/sign-in imitation, credentials, Azure HTTP client, deployment or price service. Original icons/native controls are used; no protected Portal artwork or copied lessons. Normal portal navigation must load no Three/Fiber renderer, GLBs or ambient audio. Official sources are explicit outbound reference links, not runtime content ingestion.

The shared technical store retains revision validation and command replay. The new service-types record validates exact event shape/version/size/count, pins technical attempt and command prefix, rejects stale writes, quarantines unknown/corrupt data and reports denied storage as memory-only. Local records remain editable and non-authoritative. Clearing the new record cannot clear legacy awards or technical resources; existing explicit all-data deletion includes it. Never expose learner save exports in committed screenshots or logs.

## G1.3 presentation and audio

Instruction sequences/cues are finite compiled local definitions: no remote scripts, arbitrary HTML, LLM, speech service or Learn API. Timers/camera/audio cannot emit authoritative learning events. A seventh small versioned presentation record validates exact keys/ranges; corrupt/unknown/conflicting/denied storage keeps safe memory-only preferences and never erases older work. All-data deletion clears this key even when game is unmounted. The only new media request is the allowlisted local WAV after explicit enable. Browser autoplay/resume errors are caught; no policy bypass. Local CC0 provenance/hash/budget checks extend assets:check. Hidden tabs attenuate and route unmount disposes audio; no analytics or microphone permission.

## G1.2 non-evidentiary orientation

The sixth local key azurelab.orientation.v1 holds only validated schema/seen/allowlisted-goal preferences (500-character cap). Invalid/unknown data is quarantined; conflicts/denied writes are visible and memory-only. Existing five learner stores/replay rules are preserved. Explicit all-data deletion removes orientation even with the game unmounted. Goal query parameters are allowlisted navigation requests, never technical commands/completion imports. The root uses an internal fixed redirect; the legacy route cannot redirect back into itself. No external request, asset, credential or service is added. [Progression contracts](EXPEDITION_PROGRESSION.md) specify authority boundaries.

## L1 fifth isolated local category

The new azurelab.learning.foundations.v1 key contains only pinned content/model/rubric versions, current unit and up to 500 allowlisted observations (180,000-character restore cap). Restore replays and recomputes results; imported scores/completion flags are rejected. Unknown/corrupt input is quarantined, stale-tab writes stop, denied writes warn and continue in memory. Explicit module reset does not touch legacy/game/technical data; existing all-data deletion clears this fifth category too. No implicit old-content migration or new reward exists.

The journal opens locally with native modal focus/inert background and explicit official links. Active transfer reference access records help. Local evidence cannot attest identity or prevent deliberate browser tampering; it is not an authoritative qualification. Numeric costs are invented teaching assumptions. No remote content/AI/API, executable content expressions, new dependency, credentials or asset host is introduced. Future accounts require server authorization, provenance and privacy controls.

## Current boundary

Local educational prototype: no backend, authentication, organization accounts, Azure SDK, API adapter or real infrastructure execution. Dev/start bind to `127.0.0.1`. Fonts/icons/assets are local; external links open only after selection. The Next command entry point disables framework telemetry in dev, type generation, build and start, without a required environment file.

## Input and persistence

Phase 0.5 changes presentation only: projected SVG geometry and native HTML controls introduce no WebGL, remote assets, integrations or executable learner markup. Native dialog layers use the same validated domain commands; scene coordinates/camera are not trusted persistence or evidence. Modal focus/Escape and non-spatial alternatives are checked in browser tests. The documentation gate reads repository files only and never fetches external links; links escaping the checkout are rejected.

Versioned completion IDs persist under `azurelab.progress.v1`. Phase 1A.5 also stores `azurelab.expedition.v1`: route/visits, model/layer, bounded submitted guided answers, accepted resource-group commands and mission activation. No personal details, tokens or arbitrary learner markup are collected. Parsing caps input, filters IDs/answers, rejects unknown envelope versions and replays the valid command prefix through existing validation; no stored numeric score or fabricated scope is trusted. Data deletion requires explicit confirmation and clears both categories. Scenario reset clears current commands/steps while retaining historical awards. Blocked storage falls back to memory with a visible notice; reload/navigation may lose such progress.

The parser rejects malformed/unsupported data, filters unknown IDs and deduplicates awards. XP derives from code-owned values. Creation validates names, supported regions, parent type, subscription-local uniqueness and sandbox capacity. React escapes displayed text; no HTML injection API is used.

LocalStorage can be edited, evicted, cleared or raced across tabs. It is not a secure achievement ledger. Future backends must verify attempts and deduplicate transactionally, never trust uploaded XP.

## Guided workspace — Phase 1B.1

`azurelab.chapter01.guided.v1` is a third, isolated local category. It contains only pinned versions, store revision, attempt number and up to 500 typed command/learning events (250,000-character envelope cap). Full replay validates references and derives world, receipts and guided findings; serialized worlds, XP or completion flags are not trusted. Unknown versions/corruption are quarantined with a visible warning until an explicit restart. No legacy record is promoted to chapter evidence. Explicit data deletion clears this category through the shared clear event; attempt restart preserves expedition/legacy awards. Diagnostic JSON export is local and has no import/trust-elevation path.

Commands validate envelopes, allowlisted operations/fields, name/parent/profile/dependency rules, policy and capacity. Unknown functionality returns rejection/unsupported rather than running code. Read/write denial retains memory-only work with a warning. The store checks the raw saved base before mutation/write and stops on detected concurrent change, offering export and explicit reload. This is not an atomic transaction; simultaneous writes between comparison and storage remain a local-only limitation. No credentials, real code execution, external requests or third-party infrastructure are added.

## Dependencies and secrets

Pin versions, commit lockfile, use `npm ci`, audit runtime and developer dependencies. Do not force major-version downgrades without review. `.gitignore` excludes secrets/env files, build output and learner/test artifacts. Inspect staged content before pushing. Findings and disposition are recorded in PROJECT_STATUS.md. CI is read-only and has no deployment credentials.

## Future boundary

Phase 1A proposes local workspaces, command/evidence history and checkpoint promotion in [SIMULATION_PLATFORM.md](SIMULATION_PLATFORM.md); full scenario workspaces, independent evidence and promoted checkpoints remain unimplemented; the narrower validated expedition snapshot is now persisted. Before Phase 1B, validate versioned schemas, bounded sizes, resume/migration/duplicate delivery and stale-tab conflicts. Local checksums/IDs cannot authenticate evidence. Legacy completion IDs must never become trusted attempts. Explain unsaved storage failure and separate workspace reset from explicit deletion of all local data categories.

Scenario packages are reviewed repository data with allowlisted evaluator IDs, not executable strings/remote plugins. Future terminal/KQL/Bicep teaching subsets must not execute arbitrary learner code, shell commands or outbound requests. Synthetic incident logs must contain no actual credentials, personal data or employer/customer traces. Structured reflection/evidence should minimize stored prose; permitted source links do not authorize external content ingestion or assessment scraping. Any later real-practice mode is a separate authorization/cost/security boundary.

Before accounts: session security, CSRF controls, schemas/rate limits, independent organization IDs, per-request membership authorization and isolation tests. Define export/deletion, retention and administrator visibility. Rankings require opt-in, pseudonyms, comparable conditions and withdrawal. Personal data does not implicitly become employer data.

No production resource creation, production deployment, paid service provisioning or real authentication is authorized in Phase 0. The owner explicitly approved automatic branch previews through the repository's existing Vercel integration during delivery. Report issues privately to the repository owner; no dedicated security inbox/process exists yet.
