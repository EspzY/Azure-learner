Operational basic-access wording in Learn does not become a claim of actual network configuration here.
- [VPN overview](https://learn.microsoft.com/en-us/azure/vpn-gateway/vpn-gateway-about-vpngateways) distinguishes on-premises internet VPN from Azure-to-Azure Microsoft-network VPN. [P2S documentation](https://learn.microsoft.com/en-us/azure/vpn-gateway/point-to-site-about) distinguishes OpenVPN/SSTP TLS from IKEv2 IPsec, and certificate/Entra/RADIUS compatibility. It explicitly limits Entra authentication to OpenVPN with Azure VPN Client. The revised manuscript names the TLS/IPsec distinction and retains compatibility qualifications. It does not repeat Learn VPN's universal internet/preshared-key simplification.
- [ExpressRoute encryption](https://learn.microsoft.com/en-us/azure/expressroute/expressroute-about-encryption) supports unencrypted default traffic, Direct-only physical-link MACsec, and separately usable end-to-end IPsec. nc05's gateway scope is supported; application TLS is a different protection scope.
- [Circuits and peerings](https://learn.microsoft.com/en-us/azure/expressroute/expressroute-circuit-peerings) supports separate private/Microsoft routing domains and public-address requirements. [Coexistence](https://learn.microsoft.com/en-us/azure/expressroute/expressroute-howto-coexist-resource-manager) explicitly confines the documented VPN failover to private-peering VNet connectivity. [ER overview](https://learn.microsoft.com/en-us/azure/expressroute/expressroute-introduction) distinguishes built-in redundancy, additional failure isolation, Premium geographic reach and on-premises Global Reach. The manuscript correctly qualifies the simplified Learn wording.
- [Private Endpoint overview](https://learn.microsoft.com/en-us/azure/private-link/private-endpoint-overview) supports private subnet NIC, target subresource, Approved/Pending and connected-network prerequisites. [Storage private endpoints](https://learn.microsoft.com/en-us/azure/storage/common/storage-private-endpoints) explicitly separates public-access controls, requires separate service endpoints, and preserves normal connection strings rather than `privatelink` URLs. [Storage firewall/authorization](https://learn.microsoft.com/en-us/azure/storage/common/storage-network-security) supports independent public-source and data-authorization controls; its current product scope must not be generalized to all private services.
- [DNS integration](https://learn.microsoft.com/en-us/azure/private-link/private-endpoint-dns-integration) supports shared-zone client links and reachable on-premises resolver/forwarder chains; service-appropriate public-zone forwarding matters. [Private DNS values](https://learn.microsoft.com/en-us/azure/private-link/private-endpoint-dns) distinguishes DNS answers from access control. The teaching correctly keeps normal hostname, service-specific DNS, path, approval and authorization separate.
