## Finding and disposition

**DATA-AUDIT-001 — MAJOR, open: analysis accepts inherited or unbounded identity/input fields.** The command path requires own fields, but `analysis.ts` initially did not apply the same boundary to database analysis or the shared identity. A direct executable probe imported the actual TypeScript files, created actual proposed PostgreSQL/database/firewall/binding records, and reproduced:

- `Object.create({connectionId, sourceIp})`, and an own `connectionId` with inherited allowed `sourceIp`, returned `configuration-consistent`. No explicit source IP existed in the input's own JSON fields.
- `Object.create({workspace, model, revision})` passed identity validation and returned `configuration-consistent`, while the output spread omitted all three identity fields. The result was therefore not revision/workspace bound.
- `null` and `undefined` identities threw before a structured denial; an extra own identity field with an inert sentinel value was copied into the returned result. Both analyses use this shared result/identity boundary.

This violates explicit caller input, bounded secret-free output and revision-bound analysis. The defect is reported to the integration owner and author. No current host endpoint exposes this component, so the audit does not claim a deployed exploit. It still blocks component approval. Required disposition: reject malformed/inherited/unknown identity and input fields without executing accessors or throwing; construct only supported output fields; represent an invalid identity explicitly as unbound, rather than fabricating a workspace/revision. Relevant adversarial tests and a fresh stamped affected review are required. No accepted-limitation disposition is used.
