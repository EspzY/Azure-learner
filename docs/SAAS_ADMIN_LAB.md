# Fictional SaaS administration laboratory

Reviewed 2026-10-25 against general administration principles: [users and licenses](https://learn.microsoft.com/en-us/microsoft-365/admin/add-users/add-users?view=o365-worldwide), [least-privilege roles](https://learn.microsoft.com/en-us/microsoft-365/admin/add-users/assign-admin-roles?view=o365-worldwide), [departure workflow](https://learn.microsoft.com/en-us/microsoft-365/admin/add-users/remove-former-employee?view=o365-worldwide). Original fictional UX/rules; not Microsoft 365 fidelity or an Azure ARM service.

Three fixed fictional identities (Mina, Leo, Erin), Mina initially service-admin and Leo support-admin, two license seats, account blocking, member/support-admin/service-admin roles and team/link sharing. Role capability descriptions are local training rules. License assignment does not grant administrative privilege. Blocking an account does not silently revoke its license, remove data or prove that previously copied data/sessions are gone.

Commands: assign/release license, change role, block/unblock sign-in, change sharing and record departure-data review. Exact allowlisted values, existing identity, seat limit, revision and delivery validation precede immutable mutation. Every outcome is logged; duplicate delivery is idempotent. Unknown operations never succeed. Store is separate, versioned, runtime validated and replayed; corrupt/stale state blocks changes, denied writes warn, reset retains bounded history. No passwords, invitations, authentication, real persons, billing or external calls.

Guided sequence: inspect accounts/license limit → intentionally attempt full-capacity assignment → inspect rejection → release a seat → assign Erin → choose least-privilege role → restrict link sharing → block departing Mina → remove unnecessary role/license → record explicit data review → inspect history → return to exact SaaS lesson. Decisions alter actual product state and are visible after reload.

Independent changed context: depart Leo, constrain sharing and administrator access without exceeding seats. Evaluate post-boundary operations plus final supported state and explanation of retained customer duties. Old guided work, toggling a control repeatedly, visiting history or reading a hint never establishes independent mastery. Human SME and learner review are pending.

The compact guide changes its instruction and technical reason from actual validated state. After an explicit reset, it returns to the capacity investigation in a new bound session, preserving the abandoned/submitted history. Independent mode keeps the changed requirement and withholds solution criteria until delivery or explicit help. The history displays requested values alongside each deterministic receipt. The course debrief names the actual reviewed account, role, license/block state and sharing configuration.
