## One inventory

The root ChapterProvider owns GuidedStore and the existing azurelab.chapter01.guided.v1 record. Portal commands use its command-event port with expected world revision and a stable delivery ID. Review is a dry validation against the current engine; only explicit Create dispatches. A rejection adds an actual receipt without adding a resource. Successful creation derives inventory, detail properties, notifications and graph from the resulting world. No portal-specific resource copy or manual synchronization exists.

Portal command submissions do not silently rebind old Chapter01 learning roles. Existing role bindings, predictions, explanations and guided findings remain intact. Current resource inspection can still expose the same deterministic receipt/policy mechanics. Supported technical commands: CreateGroup, DeleteEmptyGroup, CreatePlan and CreateWebApp. Unsupported fields/operations remain unsupported; no HTTP Azure adapter is introduced.

It has no real SKU, runtime deployment, global hostname availability, cost, network, health, RBAC or zone model. Cross-group hosting and cascading deletion are unsupported approximations. Tags may be explained but are not accepted as discarded fields. App OS/location derive from the selected plan. These limits must remain visible at creation and review.

## New module evidence

Service-types content/model/rubric versions are pinned independently of old saves. Allowlisted observations record deliberate comparisons, guided decisions, a changed-task start boundary, assistance and explicit submissions. Technical evidence stores references to the shared engine's attempt number, receipt prefix and selected resource IDs, not imported scores or another live inventory. Re-evaluation reconstructs that prefix through the existing execute function. Missing/replaced technical history yields unverifiable technical evidence, never success. A technical restart increments the existing attempt number, never migrates prior technical success, and leaves module history intact. Explicit cancellation records an abandoned attempt; it cannot become a fresh first unaided result. Export precedes optional confirmed restart. First submitted answers/help status remain visible; retries cannot become fresh unaided first attempts. No XP, mastery percentage or chapter completion is awarded.

Validate persisted JSON size, exact event shapes, IDs, versions and event count. Corruption/unknown versions are quarantined; denied storage uses visible memory-only state. Compare-before-write stops stale tabs. Clearing a module cannot delete technical resources or old awards; global explicit deletion includes the new record. Local editable records cannot attest learner identity or certify professional competence.

## Rendering, lifecycle and verification

The portal contains no Canvas, Three/Fiber import, game asset fetch or continuous frame loop. XYFlow is reused for zoom/pan/selection; typed semantic relationship buttons/list navigation provide equivalent access. React renders projections from the shared world. Native modal notifications/receipt dialogs use inert background, Escape and focus restoration. Scoped light Portal tokens avoid changing archived game styles.

Test pure navigation/search/projections, review versus commit, invalid/missing/denied commands, deterministic replay, immutable first submissions, missing technical history and corrupt/conflicting storage. Browser tests prove synchronized portal/diagram/learning, exact returns, reload, keyboard/mobile/reduced motion and no game/Azure/external requests. Automated checks do not establish visual fidelity or educational effectiveness.
Uncommitted create-form fields and session recents are transient; committed resources, assessment drafts and exact URL/history context resume. DeleteEmptyGroup remains a preserved engine capability, not an exposed Portal resource-delete menu. Confirmed shared-attempt restart and export are explicit recovery actions. Assistance tracking applies to the Portal's displayed learning/reference/relationship explanations, including direct URL/history entry; it cannot attest separate browsers, external materials or manual edits to local records. No fraud-resistant examination is claimed.
