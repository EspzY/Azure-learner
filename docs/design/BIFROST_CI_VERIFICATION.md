The [provenance record](bifrost-ci-port-provenance.json) lists all nine exact source hashes and separates source execution from this target's pending delivery.

The workflow keeps the mandatory full `npm run check` and high-severity audit in `check`, then executes four native Playwright shards in four independent PostgreSQL/Next/browser environments. Each shard builds the same actual revision with the unchanged nonhosted historical review fixture, runs the original plan gate, independently collects the full plan and all four partitions, and executes its fixed native partition. One worker, two CI retries, all existing per-case timeouts/assertions/skips, dependencies and 35-minute job caps are unchanged. Artifact actions use the exact reviewed source pins. The old fixed serial wrapper remains available and byte-identical. No Laboratory model, SQL, dependency, runtime, UI or learning authority is imported from PR75.

Bifrost retains all 468 inherited controls and adds seven desktop controls: 475 total, 426 desktop/49 compact. PR75's source profile was 425 desktop/50 compact; these different memberships are intentionally not interchangeable. The planner derives the target's exact case identities/settings and checks disjoint completeness. Actual target collection passed the original plan gate and independently proved native partitions of [119/119/119/118] with the exact disjoint full union. Every shard uploads raw logs, reports, traces/screenshots and an execution manifest, including failure diagnostics. `verify` runs after all prerequisites even when they fail, and first requires a real successful check and all four successful browser jobs on the same actual SHA and current workflow attempt. It downloads only that run/attempt's artifact names. The aggregate recollects the current full/native plans and verifies all four artifact identities, fixture/configuration/toolchain/source hashes, exact executed union, actual final outcomes/retries, every file hash and referenced attachment. Missing, duplicate, unexpected, skipped, failed, interrupted, stale, mismatched or truncated evidence fails closed. Selected shards and mixed attempts never provide full-profile credit.

Only a successful aggregate writes separate `candidate-ci-check` and `candidate-full-profile` receipts bound to the actual commit, review fingerprint and hashed aggregate evidence. The first receipt describes the actual mandatory CI check execution; it cannot infer a local pass. The immediately following strict release gate independently rereads current source, recollects the complete plan and validates the original bundle bytes/outcomes plus aggregate hash. Both strict success and final complete workflow success remain required. A source record's pending entries are not manually converted to passed from collection, targeted tests or PR75's prior run.

The original raw-base preservation guard covers every inherited path except explicitly hash-bound presentation/CI deltas. Old workflow assertions retain their bounded historical reader; the new actual-workflow test separately validates the real workflow and rejects unknown/weakened graph/environment/guard/artifact changes. Neither path relaxes the original product/activity gates.
