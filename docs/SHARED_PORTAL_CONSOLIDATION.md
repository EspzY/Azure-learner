## Implemented first vertical

- One Home composition: Azure Services, supported shortcuts, actual recently visited resources and scope navigation; the existing course training disclosure is an optional React slot owned by its original controller. No new SavvyShark logic.
- One service definition register and shared navigation/index. Existing model3.0–3.7 capability gates remain explicit; unknown or absent free models advertise no operative services. Course-only Web/plan/Policy are not advertised as operative v3 features. All Services explicitly explains the Web/plan gap.
- Home/All Services/Subscriptions/Resource Groups/All Resources use the same menu convention and components. Workspace-specific original receipt wording and supported service subsets remain honest. Existing course educational tools remain separate. This is entry-surface convergence, not identical engines.
- Both subscription lists/details show fixed simulated scope identity, actual group membership, actual resource membership, resource locations and separate group metadata locations. No billing, tenant authentication, real Azure account or CreateSubscription is implied. V3's two fixed scope IDs exactly match all frozen CreateGroup validators; the display adapter does not insert subscription objects into World.
- Free subscription detail offers explicit Resource Group creation in that selected scope. No navigation or Review creates a resource. Subscription/group links and existing filters use stable IDs, including identical allowed group names in different scopes.
- Recent resource IDs are bounded, presentation-only and scoped to the current workspace; deleted/reset resources are filtered out. No graph/inventory/progress store is introduced. Course's existing recent-navigation mechanism remains.
- Existing Portal header, Root Home, shared search input, drawer, resource list/filter/sort, Overview/Properties, creation/Review/Apply, Studio and original receipts remain in use. Free Home returns to free Home; “Til forsiden” still returns to `/`; course returns keep their exact original origin.

## Target architecture and bounded sequence

```text
Course learning layer (optional; versioned mission/evidence/assessment)
                         |
                  Shared AzureLab Portal + Studio
                         |
          Explicit WorkspaceContext + capability projection
                  /                         \
 Frozen legacy-course adapter       Versioned Laboratory engine
 (historical/fullfillable)            /                  \
                                document memory       PostgreSQL
                                free/untrusted       owned/persistent
```

The legacy adapter is a preservation boundary, not the desired permanent second simulator. No course attempt may change technical engine merely because a common page is opened.

1. **This PR:** architecture inventory and shared Home, subscriptions, catalogue/navigation. Preserve all authority bytes. Complete both-mode actual journeys and independent audit/CI/release.
2. **Next bounded resource consolidation:** specify new Laboratory successor semantics for App Service Plans, Web Apps, supported settings and original Web policy. Reuse pure validations only where identical; explicitly version new commands/World and additive SQL admission. Prove old3.0–3.7 golden replay, atomicity, idempotence, resource budgets, dependency invariants and both storage adapters. Do not register them into frozen3.7. Keep v2 originals readable/fullfillable.
3. **Shared controller/workspace facade:** extract common read projection and command/Review/result interfaces incrementally from the two controllers, preserving original per-engine request/receipt identity. Explicit purpose, engine/model, workspace identity and ownership accompany every command. A common catalogue is descriptive, never authorization. Storage adapters execute the same domain, not alternative rule engines.
4. **Approved versioned course pilot:** implement a new course-bound server workspace and separately versioned evidence adapter, as detailed in [course integration plan](LABORATORY_COURSE_INTEGRATION_PLAN.md). Explicit Start binds course/activity/attempt to workspace/model/technical boundary; freeze through at submission. Free client-owned replay is not durable assessment attestation. Test help denial, first/retry/abandon, Journal/resume, reset and historical replay before activation.
5. **Optional AZ-900 successors:** only new versioned activity/rubric/store contracts after review, never reinterpret active old attempts or old results. The old v2 execution path may remain historical compatibility; no automatic migration, matching-name identity join, copied World, or arbitrary imported state.

Full technical consolidation is **not accepted yet**: the same RG operation in legacy course and free mode still uses different frozen evaluators/request identities. This PR cannot honestly pass that future acceptance item. The next pilot must demonstrate one actual engine with distinct owned course/free workspaces and preserved old technical/learning evidence.
