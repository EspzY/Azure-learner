# Product vision

AzureLab helps professionals understand Azure by exploring, configuring and eventually troubleshooting infrastructure. Initial language: Bokmål, retaining Azure service names in English. The working title is AzureLab.

The first audience has some cloud exposure and needs a structured route towards operations, application management and architectural advice. Future company training is possible, but personal data, identities and infrastructure must remain independent. No employer/customer information belongs in the prototype.

## Principles

1. Let learners decide and observe consequences.
2. Reveal relationships spatially, then explain them contextually.
3. Label simplifications and simulated actions honestly.
4. Separate participation XP, demonstrated competence and exam readiness.
5. Provide keyboard and narrow-screen paths; visual richness supports comprehension.

## Phase 0 proof

Can learners explain where a resource group belongs and why its metadata region does not constrain a resource's region after using the workbench? One hierarchy, one creation assignment and three original questions test this premise. The single mission is playable; surrounding pages do not pretend to contain a complete curriculum.

## Future experience

- Azure Universe: service/deployment models, shared responsibility, identity, governance, geography and service relationships.
- Workbench: supported configurations, dependencies and deterministic consequences.
- Missions: realistic briefs, constraints, validation, feedback, hints and reflection.
- Progression: activity XP, evidence-based topic mastery and responsible achievements.
- Certification paths: versioned optional credential mappings over stable competencies, independent assessments and retention checks before any readiness recommendation. Exam codes never define the product boundary.
- Assistant: explain visible state and sources; never invent a live deployment or certify competence from chat.

Success means justifying a decision and recovering from an error. Phase 1 evaluates learners before expanding breadth: observe task success, misconceptions, independent explanation and accessibility friction with consent. No analytics is implemented.

Phase 1A proposes a competency journey spanning foundations, engineering, operations and advanced design, with a persistent reference world and isolated practice/transfer workspaces. [PRODUCT_BLUEPRINT.md](PRODUCT_BLUEPRINT.md) evaluates alternatives and defines the review rubric; [LEARNING_JOURNEY.md](LEARNING_JOURNEY.md) defines the broad graph and specialist routes. These are proposals for review, not claims that those capabilities exist. Visual depth supports the task; educational depth requires causal decisions and independent evidence.

## Non-goals

A static documentation aggregator, generic LMS, exam dumps, portal clone, full Azure emulation or ornamental 3D. No production integrations or exam-pass guarantees.
